# AI 어시스턴트 상세설계

소스: `components/AiAssistantButton.tsx`, `components/AiChatPanel.tsx`, `components/AiUnlockPanel.tsx`, `components/GeminiIcon.tsx`, `hooks/useAiAssistant.ts`, `lib/ai/*`, `app/api/ai/*`

## 역할

자연어 요청을 받아 다섯 가지 일을 한다. 보드를 바꾸는 네 가지는 모두 저장 여부를 사용자가 결정한다.

- **생성**: 메모, 표, Mermaid 카드를 임시 카드로 만들어 보드에 올린다.
- **재배치**: 이미 보드에 있는 카드의 위치를 다시 잡는다. 내용은 바꾸지 않고 좌표만 바꾼다.
- **고치기**: 이미 있는 카드의 내용을 바꾼다. 좌표와 크기는 건드리지 않는다.
- **지우기**: 이미 있는 카드를 지운다. 저장 전까지는 화면에서만 사라진다.
- **사용법 안내**: Meldrift Free Edition 조작법 질문에 함수 호출 없이 말로 답한다.

## 본판 Meldrift와 다른 점

Free Edition는 어시스턴트가 유일한 서버 기능이다. 본판에서 그대로 가져오면 안 되는 차이가 셋 있다.

| 항목 | 본판 | Free Edition |
| --- | --- | --- |
| 접근 통제 | 로그인 + 관리자 승인 | 어시스턴트 전용 비밀번호 |
| 카드 저장 | 카드마다 API 요청 | 로컬 상태에 확정 후 브라우저 SQFree Edition 자동 저장 |
| 이미지 생성 | Gemini 이미지 모델 + Cloudinary 업로드 | 없음; 사용자 선택 파일만 브라우저 BLOB으로 저장 |

Free Edition는 사용자가 직접 고른 이미지를 압축해 SQFree Edition BLOB으로 저장하지만 AI 이미지 생성은 지원하지 않는다. 생성 비용과 저장 파일 증가를 별도 동의 없이 발생시키지 않기 위해 첨부는 Mermaid와 표뿐이며, 프롬프트도 "AI 그림 생성은 못 한다"고 명시한다. 이미지 카드는 지우기 대상으로만 다룬다.

## 비밀번호 잠금

Free Edition에는 로그인이 없다. 그런데 호출 비용은 `AI_API_KEY`를 등록한 서버 소유자에게 청구되므로 어시스턴트만은 아무나 쓰지 못하게 막아야 한다.

### 왜 서버에서 검사하는가

- `AI_PASSWORD`를 클라이언트로 내려 비교하면 번들에 문자열이 그대로 남는다.
- localStorage에 `unlocked=true` 같은 플래그만 두면 개발자 도구 한 줄로 우회된다.
- 둘 다 곧 API 비용으로 돌아온다. 그래서 **실제 게이트는 `POST /api/ai/chat`에 있고, 매 요청마다 쿠키를 다시 검증한다.** 클라이언트 상태는 잠금 화면을 다시 띄우지 않기 위한 UX일 뿐이다.

### 세션을 어떻게 유지하는가

브라우저가 상태를 자동으로 기억해 주지는 않는다. 다만 **쿠키는 브라우저가 매 요청에 자동으로 실어 보낸다.** 그래서 한 번만 입력하면 된다.

Vercel 서버리스에는 세션을 둘 저장소가 없고, Free Edition는 애초에 서버 DB를 쓰지 않는다. 그래서 상태 없는 서명 토큰을 쿠키에 담는다(`lib/ai/passcode.ts`).

```text
쿠키 값 = v1.<만료 epoch초>.<HMAC-SHA256 서명>
서명 키 = HMAC(고정 문자열, AI_PASSWORD)
```

- **서명 키를 `AI_PASSWORD`에서 파생시킨다.** 그래서 환경변수가 하나로 끝나고, 비밀번호를 바꾸면 이미 발급된 토큰이 전부 한꺼번에 무효가 된다.
- 쿠키 속성은 `HttpOnly`, `SameSite=Strict`, `Path=/`이고 프로덕션에서만 `Secure`다. 로컬 개발은 http라서 `Secure`를 붙이면 쿠키가 저장되지 않는다.
- **`Max-Age`를 두지 않는 세션 쿠키다.** 브라우저를 닫으면 사라진다. 탭 복원으로 세션이 되살아나는 경우가 있어 토큰 자체에도 `aiSessionMaxAgeSeconds`(12시간) 만료를 박아 둔다.
- 형식 오류, 서명 불일치, 만료를 모두 같은 `false`로 돌려준다. 이유를 구분해 알려주면 공격자에게 힌트만 준다.
- 비밀번호 비교와 서명 비교는 `timingSafeEqual`을 쓴다. 길이가 달라도 되도록 양쪽을 해시로 같은 길이로 만든 뒤 비교한다.
- **`AI_PASSWORD`가 없으면 어떤 입력도 통과시키지 않는다.** 설정을 잊은 서버가 무료 어시스턴트가 되는 것을 막는다.

### 무차별 대입

`lib/ai/unlock-throttle.ts`가 IP별로 실패 횟수를 세고 `maxFailedAttempts`(5)회부터 `lockoutWindowMs`(5분) 동안 429로 막는다. 잠긴 동안에는 맞는 비밀번호도 거절한다.

이 카운터는 인스턴스 하나의 메모리에만 있다. 인스턴스가 늘어나면 시도 횟수도 늘고, 재활용되면 카운터가 지워진다. **완전한 방어가 아니라 속도 제한이고, 실제 강도는 비밀번호 길이에서 나온다.** 공유 저장소를 붙이는 것은 Free Edition의 전제와 맞바꾸는 일이므로 하지 않았다.

## 진입 판정 (`handleToggleAiPanel`)

1. 이미 열려 있으면 닫는다. 단, 저장하지 않은 제안이 남아 있으면 닫지 않고 먼저 결정하라고 안내한다.
2. `GET /api/ai/status`를 **열 때마다** 조회한다. 쿠키가 만료됐을 수 있으므로 캐시하지 않는다.
3. 서버에 키나 비밀번호가 없으면 그 이유를 메시지로 띄우고 열지 않는다.
4. 열되, `unlocked`가 false면 `AiUnlockPanel`을, true면 `AiChatPanel`을 보여준다.

잠금 쿠키는 `HttpOnly`라서 클라이언트 JS가 읽을 수 없다. "지금 잠금이 풀렸는지"는 `GET /api/ai/status`가 대신 알려준다.

채팅 중 쿠키가 만료되면 `POST /api/ai/chat`이 `{ locked: true }`와 401을 돌려주고, 훅이 잠금 화면으로 되돌린다. 대화 기록은 남긴다.

## 저장이 로컬이라는 점의 파급

Free Edition의 저장은 API 요청이 아니라 `BoardClient`의 자동 저장이다. 상태가 바뀌고 편집/드로잉 중이 아니면 150ms 뒤에 snapshot 전체를 SQFree Edition 파일에 쓴다.

AI 임시 카드는 음수 ID를 쓰고, `parseBoardSnapshot`은 양수 ID만 받는다. 그래서 제안이 떠 있는 동안 자동 저장이 돌면 검증에서 실패한다. **`hasPendingAiCards`를 자동 저장과 Export 양쪽의 잠금 조건에 함께 넣는다.**

```text
자동 저장 중단: !databaseReady || isEditing || drawingMode || hasPendingAiCards
Export 잠금:    isEditing || drawingMode || hasPendingAiCards
```

`handleSavePendingCards`가 하는 일은 임시 카드에 양수 ID를 붙이고 pending을 비우는 것뿐이다. 파일에 실제로 쓰는 것은 그 순간 다시 도는 자동 저장이다.

같은 이유로 **제안을 남긴 채 패널을 닫거나 잠글 수 없다.** 닫히면 Save/Discard 바가 사라지고, 보드가 저장을 멈춘 채로 잊힌다. 두 경우 모두 "먼저 결정하라"고 안내하고 패널을 열어 둔다.

## 임시 ID

`-Date.now()`에서 시작해 1씩 **증가**시킨다. 여러 장을 한 번에 만들기 때문에 값이 겹치면 안 되고, 증가 방향이어야 저장 전에도 메모 탐색 순서가 문서 순서와 같다.

저장은 메모를 계획 순서대로 하나씩 `await` 한다. `nextPositiveId`가 직전 결과를 반영해 ID를 매기므로 순서가 그대로 문서 순서가 된다.

## 배치

모델은 좌표를 정하지 않는다. `layout`과 "어떤 메모에 어떤 카드가 붙는가"만 정하고, 좌표는 `lib/ai/board-plan.ts`의 배치기가 계산한다. Markdown 컴파일이 메모 꼭짓점 포함 여부로 카드를 고르기 때문에, 배치가 어긋나면 컴파일 결과가 통째로 달라진다.

| layout | 흐름 | 쓰는 상황 |
| --- | --- | --- |
| `column` | 세로로 쌓다가 열이 차면 옆 열로 | 처음부터 끝까지 한 줄기로 읽는 문서 |
| `grid` | 좌에서 우로 채우고 줄바꿈 | 서로 대등한 항목 나열 |
| `tree` | 깊이를 x축, 형제를 y축 | 상위-하위 구조가 있는 설계 |
| `scatter` | 보드 안에서 무작위로 뽑고 겹치면 다시 뽑기 | 순서·계층이 없는 브레인스토밍 |

- 생성 원점: 기존 카드들의 오른쪽 끝 최댓값 + 120. y는 현재 보이는 화면 상단 + 80.
- 재배치 원점: 보드 전체를 다시 정리하므로 항상 (40, 40).
- 세 방식 모두 두 불변식 위에서 돈다. 가로 간격 `pitchX`가 (메모 폭 - 겹침 + 첨부 폭)보다 크고, `sectionGap > attachmentOverlap`이다. 첨부 카드가 남의 메모 꼭짓점에 닿지 않는다는 뜻이다.
- **카드를 보드 밖에 두지 않는다.** 자리가 없으면 그 섹션을 배치하지 않고 `droppedSections`로 돌려주며, 채팅이 그 수를 알린다.
- `tree`는 자기보다 앞선 인덱스만 부모로 인정하므로 순환이 생길 수 없다.
- 난수는 마지막 인자로 주입할 수 있다. 테스트가 시드 고정 PRNG를 넣어 결과를 재현한다.

`tests/unit/ai-board-plan.test.ts`가 네 배치 방식 각각에 대해 "카드 하나가 정확히 메모 하나에만 걸린다", "메모끼리 겹치지 않는다", "보드를 벗어나지 않는다"를 여러 시드에서 전수 검증한다.

## 고치기와 지우기

둘 다 **이미 저장된 카드(양수 ID)만** 대상이다. 스키마가 ID를 양수로 제한하므로 임시 카드는 모델이 지목할 수 없다.

- 고치기는 부분 수정이 아니라 **전체 교체**다. 일부만 보내면 나머지가 사라지므로 프롬프트에서 명시적으로 막는다.
- 고치기는 좌표와 크기를 건드리지 않는다. 사용자가 맞춰 둔 배치를 AI가 흔들지 않는다.
- 같은 카드를 연달아 고치면 `pendingEdits`는 맨 처음 값을 유지한다. Discard가 항상 AI가 손대기 전 상태로 돌아간다.
- 저장할 때 지우기를 **가장 마지막에** 실행한다. 앞 단계가 실패해도 원본이 남아 있게 하기 위해서다.
- 모델이 목록에 없는 ID를 지어내면 적용 단계에서 걸러지고 "찾지 못했습니다" 안내가 나간다.

## 보드 스냅샷

클라이언트가 저장된 카드(양수 ID)만 골라 ID와 요약을 만들어 `POST /api/ai/chat`에 함께 보낸다. 메모 요약은 HTML 태그를 제거한 앞부분이고, 이미지 요약은 파일명 역할의 label 또는 기존 URL이다. 이미지 바이트는 AI 서버로 보내지 않는다. 서버는 이 목록을 신뢰하지 않고 형태와 길이만 검사한 뒤 시스템 프롬프트에 붙인다.

## 서버 계약

| 경로 | 동작 |
| --- | --- |
| `GET /api/ai/status` | 키·비밀번호 설정 여부와 현재 잠금 상태. 값 자체는 다루지 않는다 |
| `POST /api/ai/unlock` | 비밀번호 확인 → 서명 토큰을 세션 쿠키로 내려준다. 실패는 401, 잠금은 429 |
| `DELETE /api/ai/unlock` | 쿠키를 지운다. 사용자가 직접 잠글 때 쓴다 |
| `POST /api/ai/chat` | 쿠키 검증 → 키 확인 → 스냅샷 검사 → 모델 호출(폴백 포함) → 계획 반환 |

`POST /api/ai/chat`은 SQFree Edition에 아무것도 쓰지 않는다. 서버는 보드 데이터를 갖고 있지 않다.

카드를 여러 장 만드는 응답은 20초를 넘기기도 해서 `export const maxDuration = 60`을 둔다. 기본 타임아웃으로는 배포 환경에서 잘린다.

## 모델 호출 (`lib/ai/assistant.ts`)

- 공급자는 Google Gemini(`@google/genai`)다.
- `assistantModels` 순서대로 시도해 첫 성공을 쓴다. 최신 모델일수록 무료 티어 할당량이 작아 429가 먼저 나므로, 최신순이 아니라 할당량이 여유로운 순으로 둔다. `GEMINI_MODEL`을 지정하면 그 모델이 맨 앞에 온다.
- 429·500·503·NOT_FOUND는 다음 모델로 넘어간다. 그 외 오류는 재시도해도 같으므로 즉시 던진다.
- 모든 모델이 실패하면 `AssistantUnavailableError`를 던지고 라우트가 503과 안내 문구로 응답한다. 쿼터 소진과 일시적 혼잡은 사용자가 할 수 있는 일이 달라 문구를 나눈다.
- 함수 선언은 `create_board_cards`, `rearrange_board_cards`, `edit_board_cards`, `delete_board_cards` 넷이다.
- 여러 함수가 동시에 호출되면 파괴적인 순서로 하나만 고른다. 지우기 > 고치기 > 재배치 > 생성.
- 함수 인자는 zod로 다시 검증한다. JSON Schema를 통과해도 모델 출력은 신뢰하지 않는다.
- 메모 본문은 blocks 배열로만 받고 HTML은 `memoBlocksToHtml`이 만든다. 메모 표시가 `dangerouslySetInnerHTML`을 쓰므로 이 경계가 XSS 방어선이다.

## 사용법 안내

`lib/ai/meldrift-guide.ts`가 조작법을 사용자 관점으로 정리해 두고 시스템 프롬프트 끝에 붙는다. 여기 없는 기능은 없다고 답하도록 못박는다.

**본판의 같은 파일을 복사해 오면 안 된다.** 로그인·서버 저장·이미지 업로드가 없고 Export/Import가 있어 안내 내용 자체가 다르다. 조작 방식이나 컴파일 규칙이 바뀌면 이 파일도 함께 고쳐야 한다. 코드와 자동으로 연결되지 않는다.

## 환경변수

| 이름 | 필수 | 용도 |
| --- | --- | --- |
| `AI_API_KEY` | 예 | Gemini API 키. 서버에만 존재하고 클라이언트로 내려가지 않는다 |
| `AI_PASSWORD` | 예 | 어시스턴트 잠금 비밀번호. 서명 키도 여기서 파생된다 |
| `GEMINI_MODEL` | 아니오 | 대화 모델을 고정한다. 나머지는 폴백으로 남는다 |

둘 중 하나라도 없으면 어시스턴트는 꺼진 것으로 취급하고 패널이 열리지 않는다. **어시스턴트를 쓰지 않는 배포는 아무 환경변수도 필요 없다.**

- `tests/unit/ai-passcode.test.ts`: 비밀번호 비교, 토큰 왕복·만료·위조·비밀번호 교체 무효화, 무차별 대입 카운터.
- `tests/unit/ai-board-plan.test.ts`: 계획 스키마와 네 배치 방식의 기하 불변식.
- `tests/e2e/ai-assistant.spec.ts`: 비밀번호 없이는 채팅이 열리지 않는다, 맞히면 열린다, 새로고침해도 다시 묻지 않는다, 쿠키가 `HttpOnly`다, Lock이 다시 잠근다.

E2E는 `playwright.config.ts`가 개발 서버에 넣는 더미 키와 테스트 비밀번호로 돈다. 모델을 실제로 호출하지 않으므로 진짜 키를 CI에 두지 않는다.

## 알려진 특이사항

- 대화 기록은 컴포넌트 state에만 있다. 새로고침하면 사라진다. 서버에도 남지 않는다.
- 새 계획이 오면 이전 미저장 카드를 먼저 걷어낸다. 한 번에 하나의 제안만 보드에 남는다.
- **재배치로 문서 순서는 바꿀 수 없다.** 컴파일이 메모 배열 순서(=생성 순서)를 따르기 때문이다. 재배치가 바꾸는 것은 표·다이어그램이 어느 메모에 붙는지와 정돈 상태뿐이다.
- 호출 횟수 제한이 없다. 비밀번호를 아는 사람이 여러 명이 되면 요청 제한을 함께 검토해야 한다.
- 혼잡(503)은 모델과 시간대에 따라 다르다. 실측으로 순서를 정하고 폴백 목록을 항상 함께 둔다.
